# Deploying on Render

This publishes the app at a public `https://<name>.onrender.com` address in **public demo mode**:
visitors can browse the results, analyse their own images with the trained models and plan routes;
training, dataset changes, evaluation, deletion and settings are locked behind an admin token.

## What you need

- The GitHub repository (this one) and a [Render](https://render.com) account (sign in with GitHub).
- The **demo bundle** `mti-demo-bundle.zip` (trained checkpoints, results database and the 322 AI4Mars
  test images, ~183 MB). Create it with `python scripts/deploy_space.py --stage --bundle` on a machine that
  has trained models; it is written to `deploy/mti-demo-bundle.zip` with its SHA-256 in `deploy/mti-demo-bundle.sha256`.
- A **Render plan with at least 2 GB of memory (Standard)**. Measured peak memory is ~550 MB (PyTorch alone
  uses ~370 MB), which is above the 512 MB of the Free and Starter plans — the app would be killed there.

## 1. Host the bundle at a direct download link

Large model files are not stored in Git, so Render downloads the bundle when the container starts.

**GitHub Release (if the repository is public):** repository page → *Releases* → *Draft a new release* →
tag `demo-v1` → drag `mti-demo-bundle.zip` into the assets box → *Publish*. Right-click the asset → copy link:
`https://github.com/<user>/AI4Mars/releases/download/demo-v1/mti-demo-bundle.zip`.

**Hugging Face (works for private GitHub repos):** huggingface.co → *New Dataset* (public) → *Files* →
*Add file* → upload the zip. Link: `https://huggingface.co/datasets/<user>/<dataset>/resolve/main/mti-demo-bundle.zip`.

Check the link downloads the file in a private browser window (no login). Release assets of a *private*
repository are not downloadable without a token.

## 2. Create the service from the blueprint

1. Render dashboard → **New +** → **Blueprint** → connect GitHub → choose this repository → branch `main`.
2. Render reads `render.yaml` and shows the service *mars-terrain-intelligence* (Docker, Standard plan).
3. Fill in the two prompted values:
   - `MTI_DEMO_BUNDLE_URL` = the link from step 1
   - `MTI_DEMO_BUNDLE_SHA256` = contents of `deploy/mti-demo-bundle.sha256` (optional but recommended)
4. **Apply**. The first build installs PyTorch and builds the website (about 10–15 minutes).
5. When the log shows `[bundle] installed` and `Uvicorn running`, open `https://mars-terrain-intelligence.onrender.com`
   (Render shows the exact URL at the top of the service page).

Manual alternative (no blueprint): *New +* → *Web Service* → repository → Runtime *Docker*, Dockerfile path
`./deploy/render.Dockerfile`, instance type Standard, health check path `/api/health`, and the environment
variables listed in `render.yaml`.

## 3. Admin access

`MTI_ADMIN_TOKEN` is generated by Render: service → *Environment* → reveal the value. On the website go to
**Settings → Admin token**, paste it and save; locked actions then work from that browser.
Training on a web server CPU is slow and the demo bundle contains no training images, so train locally and
re-deploy a new bundle instead.

## Notes

- The filesystem is not persistent: analyses made by visitors disappear when the service restarts or redeploys
  (the bundle is re-downloaded each time). Add a Render persistent disk mounted at `/app/data` to keep them.
- `MTI_MODEL_CACHE_SIZE=1` and `MTI_MAX_OUTPUT_SIDE=1024` keep memory low; uploads stay capped at 20 MB.
- Every push to `main` redeploys automatically (`autoDeploy: true`).
- Free alternative with 16 GB RAM: Hugging Face Spaces — `HF_TOKEN=... python scripts/deploy_space.py --push --space <user>/mars-terrain-intelligence`.
